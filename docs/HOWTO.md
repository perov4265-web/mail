# Почтовый сервер: пошагово

Инструкция написана под конкретную установку:

| Параметр | Значение |
|---|---|
| Домен | `protestant.ru` |
| Имя почтового сервера | `mail.protestant.ru` |
| IP почтового сервера | `186.246.51.250` |
| Первый ящик | `partners@protestant.ru` |
| Хостинг | Sprinthost, площадка Санкт-Петербург |
| Система | Debian 13 «Trixie» |

Для другого домена подставьте свои значения — порядок шагов тот же.

---

## Шаг 1. Два вопроса хостеру

Задайте в поддержку **до** настройки, потому что от ответов зависит,
будет ли работать отправка:

1. **Открыт ли исходящий порт 25 для сервера `186.246.51.250`?**
   Формулировка: «Поднимаю корпоративный почтовый сервер для организации.
   Прошу открыть исходящий 25-й порт».
2. **Прошу настроить PTR-запись для `186.246.51.250` на имя
   `mail.protestant.ru`.**

Второе делается только через хостера: обратная зона принадлежит владельцу
диапазона адресов, из панели домена туда не попасть.

---

## Шаг 2. Запись A

В панели управления DNS домена `protestant.ru` добавьте:

| Тип | Имя | Значение |
|---|---|---|
| A | `mail.protestant.ru.` | `186.246.51.250` |

Остальные записи — после установки, у них будут значения, которые выдаст
установщик.

Проверьте с любой машины:

```bash
dig +short mail.protestant.ru @1.1.1.1
```

Ждём в ответ `186.246.51.250`. Распространение занимает от 15 минут до
двух часов.

---

## Шаг 3. Вход на сервер и подготовка

```bash
ssh root@186.246.51.250
apt update && apt upgrade -y
```

Если сервер сам не видит своё имя (`ping mail.protestant.ru` отвечает
`No address associated with hostname`, хотя через `@1.1.1.1` имя
разрешается) — это отрицательный кеш локального резолвера. Лечится так:

```bash
resolvectl flush-caches 2>/dev/null || \
  printf 'nameserver 1.1.1.1\nnameserver 8.8.8.8\n' > /etc/resolv.conf
ping -c2 mail.protestant.ru
```

Чинить это нужно до первой отправки: почтовый сервер постоянно ходит в
DNS — проверяет SPF отправителей, ищет MX получателей, обращается к
чёрным спискам.

---

## Шаг 3а. Если работаете через VNC-консоль

В веб-консоли и VNC буфер обмена обычно не работает, а дальше понадобится
перенести с сервера в панель DNS строку примерно на четыреста символов —
ключ DKIM. Перепечатывать вручную нельзя: ошибка в одном символе, и подпись
не сойдётся, а понять это можно будет только по низкой оценке mail-tester.

Заберите значение через браузер. На сервере:

```bash
ufw allow 8080/tcp
cd /opt/mailserver/docker-data/dms/config/rspamd/dkim
python3 -m http.server 8080
```

Откройте `http://186.246.51.250:8080`, щёлкните по файлу, скопируйте
значение. Затем в консоли Ctrl+C и обязательно закройте порт:

```bash
ufw delete allow 8080/tcp
```

Мастер показывает эту же подсказку на шаге с DKIM.

**Про 22-й порт.** Если SSH выключен и вы работаете только через консоль
панели, открывать его в файрволе незачем — этот порт круглосуточно
перебирают боты. Мастер спрашивает об этом и по ответу «Через VNC-консоль»
22-й порт не открывает.

---

## Шаг 4. Безопасность

Этот шаг нужен, **только если SSH включён**. При работе через VNC-консоль
панели хостинга порт закрыт снаружи, перебирать нечего, и работа под root
вполне обоснована — тогда переходите сразу к шагу 5, а `sudo` в командах
ниже просто опускайте.

Если же SSH открыт, пять минут здесь экономят много нервов позже: `root` —
единственное имя пользователя, которое ботам известно заведомо.

```bash
adduser admin
usermod -aG sudo admin
rsync --archive --chown=admin:admin ~/.ssh /home/admin
```

Проверьте вход в **новом окне терминала**, не закрывая текущее:

```bash
ssh admin@186.246.51.250
```

Работает — запретите вход по паролю:

```bash
sudo nano /etc/ssh/sshd_config
```

```
PermitRootLogin prohibit-password
PasswordAuthentication no
```

```bash
sudo systemctl restart ssh
```

## Шаг 5. Установка

```bash
git clone https://github.com/perov4265-web/mail.git
cd mail
chmod +x install.sh

# сначала посмотреть план
sudo ./install.sh --dry-run

# установка
sudo ./install.sh
```

Меню спросит домен, имя сервера, ящик, часовой пояс и пароль. Значения по
умолчанию уже подставлены под `protestant.ru`.

Пароль ящика возьмите длинный и случайный: адрес будет открыт в интернет,
и его будут перебирать.

В окне дополнительных настроек оставьте всё как есть; ClamAV включайте
только если на сервере больше 3 ГБ памяти — для одного ящика антивирус
избыточен, спам фильтрует Rspamd.

Перед началом установщик покажет сводку: систему, память, диск, состояние
порта 25 и записи A. Если порт 25 закрыт или запись A ещё не
распространилась, он предупредит, но продолжить даст.

## Шаг 6. Остальные записи DNS

Установщик напечатает готовые значения. Добавьте их в панели домена:

| Тип | Имя | Значение | Приоритет |
|---|---|---|---|
| MX | `protestant.ru.` | `mail.protestant.ru.` | 10 |
| TXT | `protestant.ru.` | `v=spf1 mx ~all` | — |
| TXT | `_dmarc.protestant.ru.` | `v=DMARC1; p=none; rua=mailto:postmaster@protestant.ru` | — |
| TXT | `mail._domainkey.protestant.ru.` | `v=DKIM1; k=rsa; p=` и длинная строка | — |

Ключ DKIM, если потерялся вывод:

```bash
sudo cat /opt/mailserver/docker-data/dms/config/rspamd/dkim/*.public.key
```

Две ошибки, на которых спотыкаются чаще всего с ключом DKIM: при
копировании из терминала в строку попадают переносы и лишние пробелы —
вставляйте одной сплошной строкой; и если панель сама оборачивает
значение в кавычки, свои добавлять не надо.

**Что означают записи.** MX говорит, куда доставлять почту для домена.
SPF перечисляет, кому разрешено отправлять от вашего имени; `~all` —
мягкий режим, письма с чужих серверов помечаются подозрительными, но не
отвергаются. DKIM — подпись, подтверждающая, что письмо не подменили.
DMARC с политикой `p=none` пока только собирает отчёты; ужесточать до
`quarantine` стоит через месяц, когда убедитесь, что всё сходится.

## Шаг 7. Проверка

**Записи на месте:**

```bash
dig +short MX protestant.ru
dig +short TXT protestant.ru
dig +short TXT mail._domainkey.protestant.ru
dig +short -x 186.246.51.250
```

Последняя команда должна вернуть `mail.protestant.ru.` — это PTR. Пусто
означает, что хостер ещё не настроил; строка вида
`250-51-246-186.static.sprinthost.ru.` — стоит запись по умолчанию, её
надо заменить.

Проверьте и обратное направление: `dig +short mail.protestant.ru` должен
вернуть `186.246.51.250`. Почтовые службы сверяют обе стороны, и если имя
из PTR ведёт на другой адрес — эффект тот же, как если бы PTR не было.

**Приём почты.** Отправьте письмо с личного ящика на
`partners@protestant.ru`, затем:

```bash
cd /opt/mailserver && sudo docker compose logs --tail 50
```

**Отправка и репутация.** Откройте mail-tester.com, скопируйте выданный
адрес и отправьте на него письмо из `mailer.py`. Вернитесь на сайт за
оценкой.

**Нужно 9 из 10 и выше.** Что обычно съедает баллы:

| Проблема | Решение |
|---|---|
| нет PTR | шаг 1, вопрос второй |
| DKIM не сходится | запись скопирована не целиком |
| IP в чёрном списке | multirbl.valli.org, подать заявку на исключение |
| нет текстовой версии письма | `mailer.py` создаёт её сам, проверьте, что письмо не пустое |

## Шаг 9. Прогрев

Новый сервер — чистый IP без репутации. Резкий старт почтовые службы
воспринимают как спам-атаку.

| Период | Писем в день |
|---|---|
| дни 1–3 | 10–15 |
| дни 4–7 | 20–30 |
| вторая неделя | 50 |
| третья неделя | 100 |
| дальше | 150–200 |

В первую волну поставьте несколько своих адресов на разных службах —
Яндекс, Mail.ru, Gmail — и посмотрите, куда письма попали. Во «Входящие»
у всех трёх — можно наращивать.

Доля отбивок за волну выше 5% — остановитесь и почистите список. Отбивки
для почтовых служб главный признак работы по непроверенной базе.

## Шаг 10. Обслуживание

```bash
# логи
cd /opt/mailserver && sudo docker compose logs -f

# ящики
sudo docker exec -ti mailserver setup email list
sudo docker exec -ti mailserver setup email add info@protestant.ru
sudo docker exec -ti mailserver setup email update partners@protestant.ru

# обновление
cd /opt/mailserver && sudo docker compose pull && sudo docker compose up -d

# резервная копия
sudo tar czf /root/mail-$(date +%F).tar.gz /opt/mailserver
```

Настройте перенос архивов на другую машину: копия, лежащая на том же
сервере, копией не является.

Сертификат продлевается сам — задание в `/etc/cron.d/mailserver-cert`
проверяет срок раз в неделю, журнал в `/var/log/certbot-renew.log`.

Раз в месяц проверяйте IP на multirbl.valli.org.

## Если что-то пошло не так

**`ping mail.protestant.ru` не работает с самого сервера, но работает
через `@1.1.1.1`** — отрицательный кеш резолвера, шаг 3.

**Письма не уходят, в логе `Connection timed out`** — закрыт исходящий
порт 25, шаг 1.

**Gmail отвергает письма** — чаще всего нет PTR либо не сходится DKIM.

**Сертификат не выпустился** — запись A ещё не распространилась или
80-й порт занят. Освободите порт и повторите:

```bash
sudo docker run --rm -p 80:80 \
  -v /opt/mailserver/docker-data/certbot/certs/:/etc/letsencrypt/ \
  certbot/certbot certonly --standalone -d mail.protestant.ru
```

**Контейнер перезапускается по кругу** — смотрите логи, обычно не хватает
памяти. Проверьте `free -m`, добавьте swap.

**Вход в ящик не проходит** — логин вводится целиком, с доменом:
`partners@protestant.ru`, а не `partners`.
