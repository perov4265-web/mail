# mail — почтовый сервер за один запуск

Мастер установки почтового сервера на свой домен для Debian и Ubuntu.
Ведёт по шагам: спрашивает параметры, показывает, **что и где** настроить,
сам проверяет каждый шаг и не идёт дальше, пока предыдущий не сделан.
Внутри — [docker-mailserver](https://github.com/docker-mailserver/docker-mailserver):
Postfix, Dovecot и Rspamd в одном контейнере.

Инструкция встроена в сам скрипт: отдельную документацию читать не нужно,
каждый экран объясняет, что происходит и что от вас требуется.

Рассчитан на случай «свой домен, один-два ящика, нужна рассылка».
Занимает 1–2 ГБ памяти и не трогает порты 80 и 443 — на этом же сервере
может жить сайт.

---

## Быстрый старт

```bash
git clone https://github.com/perov4265-web/mail.git
cd mail
chmod +x install.sh
sudo ./install.sh
```

Откроется меню: домен, имя сервера, ящик, часовой пояс, пароль,
набор дополнительных настроек. Дальше — проверка окружения и установка
с индикатором выполнения.

Посмотреть план, ничего не меняя:

```bash
sudo ./install.sh --dry-run
```

## Ход работы

| Шаг | Что происходит |
|---|---|
| 0 | Приветствие, план работ |
| 1 | Параметры: домен, имя сервера, IP, ящики, приём мусора, часовой пояс, пароль |
| 2 | Проверка сервера и **исходящего порта 25**, с готовым текстом запроса в поддержку |
| 3 | Запись A: где именно её добавить, и проверка в цикле |
| 4 | Установка в 14 шагов с индикатором |
| 5 | Записи MX, SPF, DMARC, DKIM — по одной на экран, каждая проверяется |
| 6 | PTR: почему нельзя сделать самому и что написать хостеру |
| 7 | Проверка приёма и отправки, mail-tester |

| 8 | Самопроверка из 11 пунктов и список того, что осталось |

Каждая проверка идёт циклом: не прошла — исправляете и жмёте «Проверить»
ещё раз, либо пропускаете и возвращаетесь позже.

## Устойчивость к сбоям

Мастер не падает на первой ошибке. Результат каждого шага проверяется
отдельной функцией — не по коду возврата, а по факту: запущен ли
контейнер, слушается ли порт 25, создан ли ящик, есть ли ключ DKIM.

Если шаг не удался, мастер сначала пробует починить сам:

| Что сломалось | Что делает мастер |
|---|---|
| не ставятся пакеты | `dpkg --configure -a`, чистит кеш apt, повторяет |
| не встал Docker | ставит `docker.io` из репозитория дистрибутива |
| не выпускается сертификат | останавливает nginx или apache, занявший порт 80, повторяет |
| контейнер не поднялся | перезапускает Docker, пересоздаёт контейнер |
| не создаются ящики | ждёт готовности сервера и повторяет |

Не помогло — показывает четыре варианта: повторить, починить ещё раз,
пропустить, прервать. Пропущенное попадает в итоговый список «осталось
сделать» с готовыми значениями.

Отдельный случай — сертификат. Если выпустить его не удалось, сервер
переводится на самоподписанный: почта работает сразу, а команда для
выпуска настоящего сертификата выдаётся в конце.

## Внутренние шаги установки

| Шаг | Действие |
|---|---|
| 1 | Обновляет список пакетов, ставит базовые утилиты |
| 2 | Задаёт имя сервера и часовой пояс |
| 3 | Создаёт файл подкачки, если памяти мало |
| 4 | Останавливает postfix, exim, dovecot — они занимают почтовые порты |
| 5 | Настраивает файрвол ufw, не закрывая SSH |
| 6 | Ставит Docker, если его нет |
| 7 | Пишет `compose.yaml` для docker-mailserver |
| 8 | Выпускает сертификат Let's Encrypt |
| 9 | Ставит задание cron на продление сертификата |
| 10–12 | Загружает образ, запускает контейнер, ждёт готовности |
| 13 | Создаёт ящики, алиасы `postmaster@`, `abuse@` и правило для несуществующих адресов |
| 14 | Генерирует ключ DKIM |

В конце печатает готовые записи DNS с подставленными доменом и IP.

## Письма на несуществующие адреса

Мастер спрашивает, что делать с письмом на адрес, которого нет —
например, на `pastor@example.ru`, если такого ящика не заводили.

- **Складывать в главный ящик** — ни одно письмо не потеряется: ошибся
  отправитель в адресе или писал на старый, всё равно дойдёт. Обратная
  сторона: туда же польётся спам, который рассылают по словарю адресов.
- **Отклонять** — отправитель получит уведомление, что адреса нет.
  Спама меньше, но письмо с опечаткой пропадёт.

Настраивается алиасом `@домен` → главный ящик; поменять решение потом
можно одной командой.

## Ключи запуска

| Ключ | Смысл |
|---|---|
| `--domain <домен>` | почтовый домен |
| `--host <fqdn>` | имя сервера |
| `--mailbox <имя>` | первый ящик без `@домена` |
| `--tz <зона>` | часовой пояс |
| `--no-ui` | без псевдографики, простые вопросы |
| `--dry-run` | показать план, ничего не менять |
| `--uninstall` | удалить установленное вместе с почтой |
| `-h`, `--help` | справка |

Неинтерактивный запуск:

```bash
sudo ./install.sh --no-ui --domain example.ru --mailbox info
```

## Требования

- Debian 12/13 или Ubuntu 22.04/24.04/26.04, чистая система;
- 2 ГБ памяти, 20 ГБ диска (с антивирусом ClamAV — 3 ГБ);
- домен с доступом к DNS-записям;
- открытый исходящий порт 25 и возможность прописать PTR у хостера.

Меню требует терминала. При запуске без tty установщик сам переходит
к простым вопросам.

## После установки

Что настроить у регистратора домена и как проверить результат —
в [docs/HOWTO.md](docs/HOWTO.md): пошагово от заказа VDS до прогрева
рассылки, с разбором типовых сбоев.

Шаблоны записей DNS — в [contrib/dns-records.txt](contrib/dns-records.txt).

### Обслуживание

```bash
# логи
cd /opt/mailserver && docker compose logs -f

# ящики
docker exec -ti mailserver setup email list
docker exec -ti mailserver setup email add info@example.ru
docker exec -ti mailserver setup email update info@example.ru

# обновление
cd /opt/mailserver && docker compose pull && docker compose up -d

# резервная копия
tar czf mail-$(date +%F).tar.gz /opt/mailserver
```

Журнал установки — `/var/log/mailserver-install.log`,
журнал продления сертификата — `/var/log/certbot-renew.log`.

---

## Удаление

```bash
sudo ./install.sh --uninstall
```

Удаляет контейнер, каталог `/opt/mailserver` со **всей почтой** и задание
cron. Сделайте резервную копию заранее.
